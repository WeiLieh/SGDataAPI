## Data Sources

- [2026-10-15] All data comes from data.gov.sg, fetched by the app's own server code (api/), with no MCP server, no third-party wrapper and nothing bundled or invented.
- [2026-10-15] Real-time API family: base https://api-open.data.gov.sg/v2/real-time/api; source kind "realtime" with a path such as "/pm25". Optional header x-api-key raises the rate limit. Success is HTTP 200 with code 0 and errorMsg "". Errors: 400 code 4 ERROR_PARAMS; 404 code 17 REAL_TIME_API_DATA_NOT_FOUND; 429 code 24 TOO_MANY_REQUESTS; error bodies carry data: null and a human-readable errorMsg.
- [2026-10-15] Most non-weather datasets on data.gov.sg are not part of the real-time family and use a different API keyed by their d_ dataset ID. Not built yet: when the first such dataset is added, read that dataset's API page on data.gov.sg, add a new source kind with its own fetch function in api/_lib/, and record it here.
- [2026-10-15] data.gov.sg rate-limits requests without a key (HTTP 429, code 24). Therefore successful responses are cached at Vercel's CDN (Cache-Control: public, s-maxage, stale-while-revalidate), nothing retries automatically, and the optional key is supported.
- [2026-10-15] Licence: Singapore Open Data Licence version 1.0 (https://data.gov.sg/open-data-licence). The app must show: "Contains information from PM2.5 accessed on <date> from data.gov.sg which is made available under the terms of the Singapore Open Data Licence version 1.0", linking to the licence.

## Datasets

- [2026-10-15] pm25 — "PM2.5", category "Air quality", agency National Environment Agency (NEA), dataset ID d_e1058d6974c877257e32048ab128ad83, dataset page https://data.gov.sg/datasets?query=pm2.5&resultId=d_e1058d6974c877257e32048ab128ad83, endpoint GET https://api-open.data.gov.sg/v2/real-time/api/pm25. Unit µg/m³, integer readings. This is the 1-hour PM2.5 concentration, never PSI; no PSI is derived from it.
- [2026-10-15] pm25 query: no date = latest reading; date=YYYY-MM-DD = every reading of that SGT day; date=YYYY-MM-DDTHH:mm:ss = latest reading at that SGT moment. The date must be a real calendar date/time and not later than now in SGT. data.paginationToken appears only with a date and only when another page exists; the server follows it (at most 5 pages, else 502). paginationToken is not a client parameter.
- [2026-10-15] pm25 real response vs spec (the real response wins): data.regionMetadata (camelCase), lowercase region names, plain date "2026-10-15", SGT timestamps with offset, readings under items[].readings.pm25_one_hourly. Parsing stays defensive: region names trimmed and lowercased on both sides, any ISO 8601 timestamp with an offset accepted, a region missing from a reading is null (not 0), and a region with readings but no metadata is kept without coordinates.
- [2026-10-15] pm25 normalized shape: { unit: "µg/m³", regions: [{ id, name, latitude, longitude }], readings: [{ timestamp, updatedTimestamp, values: { [regionId]: number | null } }] }. Region order central, north, south, east, west, then others alphabetically; readings oldest to newest, duplicate timestamps dropped. timestamp is the hour covered; updatedTimestamp is when data.gov.sg published it; both are shown.
- [2026-10-15] Test fixtures: tests/fixtures/pm25-latest.json is the real reply from the brief's Appendix, verbatim. pm25-error-400/404/429.json are built from the documented error codes and names (code 4 ERROR_PARAMS, 17 REAL_TIME_API_DATA_NOT_FOUND, 24 TOO_MANY_REQUESTS, data: null). Their errorMsg wording was not captured live; replace them with real replies when one is seen.
- [2026-10-15] pm25 caching: 300 s with no date or a date on today's SGT date; 86400 s for an earlier day.
- [2026-10-15] pm25 bands live only in shared/datasets/pm25-bands.ts (source https://www.haze.gov.sg): NEA's 1-hour PM2.5 concentration bands — Band I Normal 0–55, Band II Elevated 56–150, Band III High 151–250, Band IV Very High 251 and above, in µg/m³. These values come from NEA and must be checked against haze.gov.sg whenever they are touched. A null reading never gets a band.

## Decisions

- [2026-10-15] App name: SG Weather. Mobile-first Vite + React + TypeScript web app plus two Vercel serverless functions. Read-only: no database, login, analytics or cookies.
- [2026-10-15] No fallbacks: a failed call is shown as a failure, never replaced with bundled, sample, browser-cached or made-up values; no screen ever shows a reading data.gov.sg did not return for the current query.
- [2026-10-15] Dataset registry (shared/datasets/registry.ts) is the extension point. Each definition: id, title, category, agency, datasetId, datasetPage, source (discriminated union on kind; only "realtime" implemented), params (validators returning a cleaned value or a one-sentence error; unknown params rejected), schema (zod), normalize(body), cacheSeconds(params). api/_lib dispatches on source.kind with an exhaustive switch. src/views/index.ts maps every DatasetId to a screen with `satisfies Record<DatasetId, ...>`.
- [2026-10-15] Adding a real-time dataset touches only: shared/datasets/<id>.ts, one line in the registry, src/views/<Name>View.tsx plus one line in src/views/index.ts, a fixture with tests, and an entry here. Nothing in api/ changes. api/data.ts fetches only URLs built from registry entries, never a path or URL from the request.
- [2026-10-15] Besides the fields above, each definition also carries three small pure helpers the generic server code needs: mergePages(bodies) (combines the pages of a paginated reply before normalize), isEmpty(data) (detects "success with no readings") and notFoundMessage(params) (the 404 sentence, e.g. "data.gov.sg has no PM2.5 readings for <date>."). Keeping these in the definition is what lets api/ stay unchanged when a dataset is added.
- [2026-10-15] /api/data error map: upstream 400 → 400 with errorMsg; upstream 404 or success with no readings → 404 "data.gov.sg has no PM2.5 readings for <date>." / "...right now."; upstream 429 → 429 with Retry-After passed on; upstream 5xx → 502 "data.gov.sg returned HTTP <status>."; HTTP 200 with code ≠ 0 → 502 with errorMsg; non-JSON or schema mismatch → 502 "...unexpected format." (zod issues logged); timeout (10 s) → 504; network failure → 502 "Could not reach data.gov.sg."; more than 5 pages → 502; anything else → 500 "Unexpected server error." (stack logged). Messages at most 200 characters. Never retry automatically.
- [2026-10-15] Upstream statuses the brief does not name (e.g. 401, 403, other 4xx) are answered like 5xx: 502 "data.gov.sg returned HTTP <status>.", since the fault is upstream, not in the client's request.
- [2026-10-15] Success replies: 200 { ok: true, dataset, params, source: { name, agency, datasetId, datasetPage, endpoint }, fetchedAt, data } with Cache-Control: public, s-maxage=<cacheSeconds>, stale-while-revalidate=<cacheSeconds>. Failures: { ok: false, dataset, error: { status, upstreamStatus, upstreamCode, upstreamName, message } } with Cache-Control: no-store. Every reply is JSON (application/json; charset=utf-8) with X-Content-Type-Options: nosniff. Server logs: one line per failure, never the key or request headers.
- [2026-10-15] /api/health calls the PM2.5 latest endpoint once with a 5-second timeout and answers { ok, checkedAt, keyConfigured, upstream: { endpoint, status, code, latencyMs, latestTimestamp, message }, datasets }, 200 when data.gov.sg answered with valid data, 503 otherwise, Cache-Control: no-store.
