# CLAUDE.md — instructions for every session in this repository

1. **Read first.** Before changing anything, read `MasterPrompt.md` (the original brief, never edited) and `Context.md` (every later instruction and decision). Where they differ, the newer Context.md entry wins.
2. **Record changes in Context.md**, in the same commit as the change: whenever the owner gives new context or a new instruction, and whenever a change alters what the app shows, how it behaves, or how it is built or deployed. Each entry is one bullet starting with the Singapore date as `[YYYY-MM-DD]`, under one of the sections "Deployment & Environment", "Data Sources", "Datasets", "UI", "Decisions", "Git & Release Workflow". When an entry replaces an earlier one, keep the old one, append `(superseded [YYYY-MM-DD], see below)` to it, and say in the new entry what it supersedes.
3. **Record errors in error_log.txt**, in the same commit, one line per error:
   `[YYYY-MM-DD] <Kind> Error: <what happened, with the exact message, HTTP status or failing command> (Resolved: <fix> | Open: <next step> | Not a code error: <why>)`
   Kind is one of Build, Type, Test, API, Deploy, Git, Tool, Display, Bug. Log every error: failed tests, type errors, failed commands, git and push failures, permission or tooling failures, upstream API failures seen during development. When a logged error is fixed later, update that line's status in place instead of adding a new line.
4. **Never write a key, token or secret** into any file (MasterPrompt.md, Context.md, error_log.txt, README.md, code, comments, tests, logs). `DATAGOV_API_KEY` is read only from `process.env` in `api/_lib/`, never sent to the browser, never put in a URL, response or log. Never create a variable whose name starts with `VITE_`.
5. **Add datasets only as described in step 5 of MasterPrompt.md**: `shared/datasets/<id>.ts`, one line in `shared/datasets/registry.ts`, `src/views/<Name>View.tsx` plus one line in `src/views/index.ts`, a fixture with tests, and a Context.md entry. For a real-time dataset nothing in `api/` changes. A dataset outside the real-time API family needs a new source kind with its own fetch function in `api/_lib/` (read that dataset's API page on data.gov.sg first) and a Context.md entry.
6. **Look and feel comes only from the entries under "UI" in Context.md**, never from your own design choices. No styling library unless a UI entry says so.
7. **Run `npm run check` before every commit** (typecheck, tests, build). Never skip, disable or delete a test to get a green check.
8. No new npm packages beyond those listed in MasterPrompt.md step 2 without asking the owner. npm only; `package-lock.json` is the only lockfile.
9. No fallbacks: a failed call is shown as a failure, never replaced by bundled, sample, browser-cached or invented values.
10. Git: follow "Git & Release Workflow" in Context.md (branch + pull request into main once the app is live on Vercel).
